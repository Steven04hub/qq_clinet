# Jev 初次接入测试

日期：2026-09-20。模型：`jev-1.13.0`。实际调用 TypeSafe API，使用虚构中文聊天，没有上传真实群聊记录，也没有向 QQ 发送测试消息。

本报告是内部“机器人是否适合接话”判断的历史基准，不是群友自己的决策工具测试。内部路由与五项分数不会发到群里；公开工具会单独处理用户提供的是非问题或有限选项问题，详见 [两个用途及接入说明](jev-reply-gate.md)。

## 结果

- 首次认证验证 HTTP 200，用时约 1.95 秒。
- 随后 18 个场景全部调用成功，返回类型与分数字段合法，无超时或认证错误。
- 7 个场景给出明确判断：6 个可接话、1 个静默，全部符合样本作者预设标签。
- 11 个场景回退，不计为正确。其中包含 3 个可回可不回的场景。
- 对 15 个明确标签样本，直接决策覆盖率 46.7%。这个小样本不能说明真实群聊准确率。
- 18 次请求耗时中位数 336.5 ms，最慢 1039 ms。另一个首次冷请求约 1.95 秒；这些是本机本次观测，不是服务保证。
- 输入 token 共 26,983。未测量完整 DeepSeek 生成耗时或 QQ 端到端延迟。

当前提示和初始阈值偏保守：话题已结束、纯复读、两人确认事项等场景仍经常回退。没有按这 18 个样本临时调阈值后再声称准确率提升。建议先运行对照模式，后续用未参与调参的真实脱敏窗口验证。

## 可行性判断

工程方案可行。将便宜的决策步骤放在生成步骤前，能够跳过明确无需回复的轮次；不确定时保留 DeepSeek 判断，避免强制插话或长期沉默。

本次结果还不足以证明值得全面替换：只有 1/18 的轮次能直接省去 DeepSeek 调用，其余仍会调用生成模型；正式判断模式还增加一次网络等待。对照模式则与现有生成并行，但会增加少量 API 费用。

能否更像真人，取决于上下文、私有群梗和提示效果，而不是“决策模型”这一名称。官方也提示 Jev 的主要训练语言为英语，应自行验证中文效果。[语言支持](https://docs.typesafe.ai/models)

原始分数与统计见本机 `.state/evals/jev-20260920-initial.json`；可用 `uv run --locked python -m scripts.evaluate_jev` 重跑。重跑结果可能变化，样本标签也存在主观性。
